# Validation scripts

These scripts are how each day of the repo was checked: each one compares a day's code in
`papers/<NN_name>/` with something independent of it (PyTorch built-ins or `torch.autograd`, finite
differences, closed forms from the paper, or the exercises' own tests run with the reference solutions
swapped in) and prints how closely they agree. Run them from the repo root, e.g.
`OMP_NUM_THREADS=1 python validation/day13_reference_torch.py`; a CPU is enough. Some need data that is not in
the repo: CIFAR-10 for days 08 and 28 (the day's `data/cifar-10-batches-py`, or a day directory passed as the first
argument), MNIST for days 12 and 23, Penn Treebank for day 03 (downloaded from the paper's own repo, or `$PTB_DIR`),
and the full Tiny Shakespeare `input.txt` for `day01_real_data_run.py`. Scripts that compare old and new code read
the old files from git history (e.g. commit `195dcf2`, the state before the fixes), and the plots and checkpoints
some scripts write go to the git-ignored `validation/outputs/`. Runtimes were measured single-threaded on a busy
2-CPU machine (fast = under a minute). A FAIL marked as expected, or on a pre-fix row, documents a known problem
in the old code, not a broken script.
