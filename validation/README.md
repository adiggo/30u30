# Validation scripts

These scripts are how each day of the repo was checked: each one compares a day's code in
`papers/<NN_name>/` with something independent of it (PyTorch built-ins or `torch.autograd`, finite
differences, closed forms from the paper, or the exercises' own tests run with the reference solutions
swapped in) and prints how closely they agree. Run them from the repo root, e.g.
`OMP_NUM_THREADS=1 python validation/day13_reference_torch.py`; a CPU is enough. Only three need data
that is not in the repo: `day08_alexnet_checks.py` and `day28_numgrad_and_trajectory.py` read CIFAR-10
from the day's `data/cifar-10-batches-py` (or from a day directory passed as the first argument), and
`day01_real_data_run.py` takes the path of the full Tiny Shakespeare `input.txt`. The four scripts that
compare pre-fix with patched code read the old files from git commit `195dcf2`, and the plots and
checkpoints some scripts write go to the git-ignored `validation/outputs/`. Runtimes were measured
single-threaded on a busy 2-CPU machine (fast = under a minute). A FAIL marked as expected, or on a
pre-fix row, documents a known problem in the code, not a broken script.
